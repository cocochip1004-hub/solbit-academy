# Notion 버튼/자동화 → Supabase Edge Function 매핑표

이 문서는 Notion DB의 버튼·체크박스·자동화가 어떤 Supabase Edge Function 웹훅을 호출하는지
정리한 표입니다. **새 학원(고객)에 이 시스템을 이식하면서 Notion 자동화를 다시 연결할 때** 참고하세요.

이 표는 실제 `supabase/functions/*/index.ts` 코드 상단 주석을 근거로 작성했습니다
(추측이 아닌 코드 확인). 다만 Notion 쪽 자동화 이름/조건은 학원마다 약간 다를 수 있으니,
새로 연결한 뒤에는 반드시 테스트해보세요.

## 공통 규칙

- 대부분의 함수는 `x-admin-key` 헤더로 인증합니다. Notion 버튼의 "웹훅 보내기" 액션이 커스텀 헤더를
  못 보내는 경우가 있어, 많은 함수가 요청 바디의 `adminKey` 필드도 함께 확인합니다
  (`resolveAdminKeyFromRequest`). 자동화를 새로 만들 때 헤더가 안 먹히면 바디에 `adminKey` 필드를
  고정값으로 추가하세요.
- 엔드포인트 주소는 모두 `https://<이 학원의 Supabase 프로젝트 ref>.supabase.co/functions/v1/<함수명>` 형태입니다.
- pageId가 필요한 함수는 보통 자동화의 "웹훅 보내기" 본문 편집기에서 현재 페이지 ID를 넣어야 합니다.

## §9. "삭제" 버튼 공용 — cascade-delete

아래 7개 DB의 "삭제" 버튼은 모두 동일하게 `cascade-delete`를 호출합니다.
DB별로 "삭제 상태" select 속성을 각자 독립적으로 관리하므로, 자동화 설정 시 어떤 DB/페이지인지
식별할 수 있는 값(페이지 ID 등)을 웹훅 본문에 포함해야 합니다.

- 교재비(카트)(학원) DB

- 수업(학원) DB
- 학습기록(학원) DB
- 학습활동(학원) DB
- 교재배부(학원) DB
- 교재결제(학원) DB

## 17. Notion 자동화가 아닌 것들 (참고)

아래는 Notion 버튼/자동화가 아니라 웹앱(GitHub Pages)이나 예약 실행(cron)이 직접 호출합니다.
Notion 자동화 재연결 작업 범위에서 제외하세요.

- `get-report-fast`, `get-report-detail`, `get-legal-document-data`, `list-students`, `sync-student-report` — 학부모 리포트/약관 웹앱(`student_report.html`)이 호출
- `get-report-file` — 학부모 리포트에서 PDF·일반 파일 버튼을 누를 때 호출. `POST` body: `{ token, blockId }`. 보고서 토큰과 해당 캐시 내 블록 포함 여부를 검증한 뒤 최신 Notion 파일 URL을 반환. Notion 버튼/자동화 연결이나 브라우저의 관리자 키는 필요하지 않음. [본문·첨부파일 개발 문서](학생-보고서-본문-첨부파일.md) 참고
- `kiosk-checkin` — 출결 키오스크 웹앱(`attendance_kiosk.html`)이 호출 (v2.5.2: 로그인 시 `list-students?kiosk=1` 최소 목록을 받아 등록 ID 우선 처리, 서버 재검증. [키오스크 처리 흐름](키오스크-처리-흐름.md) 참고)
- `process-sync-queue`, `status-watchdog`, `sync-failure-audit`, `backfill-assignment-deadlines` — pg_cron/내부 체이닝이 호출

## 솔빛학원 적용 시 확인 사항 (원본 최신 문서 반영 후 코드·설치 스키마 대조)

- 원본 최신 commit: `ae85dae52a1cd19d255529addfa8a46c753358ef`, CHANGELOG v2.5.4. 원본은 변경하지 않는다.
- 운영 웹훅 base: `https://zidrwdvgmfmuiqggjgzm.supabase.co/functions/v1/`. 원본 URL·원본 인증키는 사용하지 않는다.
- 원본 매핑 문서의 일부 설명은 현재 코드와 다르므로 위 두 항목을 운영용으로 정정했다. 자동화가 이미 구성되어 있다는 의미는 아니다.
- `sync-registration-timetable/index.ts`에는 예전 클래스 편집 자동화가 목적을 잃었다는 설명이 있다. 함수는 종료일 후처리·복원을 수행하며, 단순 클래스 변경 자동화로 새로 연결하지 않는다.
- `_shared/reportDirtySync.ts`의 직접 변경분 조회 대상은 출석·학습기록·학습활동·보고서 4개다. `동기화 필요` 수식으로 조회한 후 속성 지문을 비교하며, 별도 스캔 예약의 존재를 이 설명만으로 가정하지 않는다.
- 최초 설치 당시 출석·학습기록·학습활동·보고서 4개 DB에는 날짜형 `학습정보 수정일`, 날짜형 `마지막 동기화`, 수식 `동기화 필요`가 있다. v2.5.5 패치로 등록에도 날짜형 `학습정보 수정일`을 추가했다. 등록의 웹훅 연결은 가능해졌으나 자동화·실제 리포트 반영은 미검증이다. 정규교재·일정에는 해당 날짜가 없으므로 이 두 곳에 `mark-report-source-dirty`를 그대로 새로 연결하지 않는다.
- `mark-report-source-dirty`는 주어진 페이지의 날짜만 기록한다. 날짜 기록 방법은 노션 자체 속성 편집 액션 또는 이 웹훅 중 하나로 구성하며, 기존 액션을 확인하지 않고 중복 자동화를 만들지 않는다.
- 정규교재·일정의 `sync-report-cache` 자동화는 위 수정일 기록 방식과 별개다. 기존 조건·본문을 확인해 운영 주소로 재연결한다.
- 발송·삭제·대량 생성 및 실제 학생 시험은 별도 승인 후 진행한다. 주소 교체만으로 인증·실동작 검증 완료를 표시하지 않는다.


### v2.5.5 후속 적용

- 원본 지침: `docs/updates/v2.5.5.md`, 원본 commit `14751d8c3d7fb67576d9a26605dd8f5c571ded6d`.
- 등록 DB 날짜 속성 `학습정보 수정일` 추가 완료. 기존 속성·수강정보 및 갤러리 뷰 구성 보존 확인. 등록 50건 모두 새 날짜 값 비움 확인. 기존 날짜·등록 데이터 백필 없음.
- 등록의 보고서 관련 속성 편집 자동화에서 현재 등록 페이지 ID를 `mark-report-source-dirty`로 전달하는 설정을 운영자가 확인한다. `학습정보 수정일` 자체의 변경은 트리거 제외.
- 노션 자체 자동화가 같은 날짜를 기록하고 있다면 중복 웹훅을 새로 만들지 않는다. 원본 문서의 인증 안내와 실제 함수의 인증 처리를 동일한 것으로 가정하지 않고 기존 운영 설정을 확인한다.
- 패치는 등록의 수정일 기록 속성 보정이다. `reportDirtySync.ts`의 직접 변경분 조회 대상 4개에 등록이 추가되거나, 별도 스캔·리포트 동기화가 자동 완료된 것은 아니다.
- 실행 코드·Supabase·Secrets·마이그레이션 변경 및 재배포 없음. 자동화 액션·웹훅 수신·리포트 반영 시험은 미검증.
